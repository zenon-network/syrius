# Syrius Documentation Portal (`website/`)

This directory contains the unified [Docusaurus v3](https://docusaurus.io/) documentation site for **Syrius**, the cross-platform non-custodial Flutter desktop wallet for Zenon Network (Network of Momentum Phase 1).

It brings two autogenerated documentation tracks under one portal:

- **User Guide** (`docs/user-guide/`) — Installation, wallet setup, core wallet features (Plasma, Staking, Pillars, Sentinels, ZTS Tokens, P2P Swaps, Accelerator-Z, WalletConnect), Ledger hardware wallet usage, node modes, security, and FAQ.
- **Developer Docs** (`docs/developers/`) — Local Flutter/Dart & FFI setup, architecture overview, feature-based BLoC rearchitecture, localization, code generation, unit/widget tests, Dockerized devnet blockchain integration tests, and contribution guidelines.

## Prerequisites

- **Node.js** `>= 22.12.0` (CI uses Node 22; tested with Node 22 and Node 24)
- **npm** (bundled with Node.js)

## Local Development

```bash
cd website
npm install
npm start
```

`npm start` launches the local development server with hot reload (default: `http://localhost:3000/syrius/`).

To preview at root `/` locally:

```bash
DOCS_BASE_URL=/ npm start
```

## Typechecking, Production Build & Local Preview

```bash
cd website
npm run typecheck
npm run build
npm run serve
```

- `npm run typecheck` runs TypeScript (`tsc`) against the config, sidebars, and custom React/TSX components.
- `npm run build` outputs the static production bundle to `website/build/`, generates the offline search index (`@easyops-cn/docusaurus-search-local`), renders Mermaid diagrams, and enforces strict link checking (`onBrokenLinks: 'throw'`, `onBrokenMarkdownLinks: 'throw'`).
- `npm run serve` serves the compiled `website/build/` output locally so you can verify production routing and local search (local search indexing only runs on production builds).

## Configuration Environment Variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `DOCS_URL` | `https://zenon-network.github.io` | Canonical site origin (no trailing slash). |
| `DOCS_BASE_URL` | `/syrius/` | Subpath mount for project sites (use `/` for root custom domains). |

## Content Structure & Sidebars

Sidebars in [`sidebars.ts`](./sidebars.ts) are autogenerated from the folder hierarchy:

- `userGuideSidebar` → `website/docs/user-guide/`
- `developersSidebar` → `website/docs/developers/`

Ordering and category titles are managed inside each folder via `_category_.json` and frontmatter `sidebar_position`.

## Deployment

### GitHub Pages (Automated CI)

Deployment is automated via [`.github/workflows/deploy-docs.yml`](../.github/workflows/deploy-docs.yml):

1. In your GitHub repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.
2. Push changes touching `website/` to `master` (or run **Actions → Deploy Documentation → Run workflow**) to publish to GitHub Pages.
3. Pull requests targeting `master` or `develop` that touch `website/` automatically run `npm ci`, `npm run typecheck`, and `npm run build` for validation without deploying.
4. For forks, `DOCS_URL` and `DOCS_BASE_URL` are automatically derived from `github.repository`. If you configure a custom domain, you may also set repository variables `DOCS_URL` (e.g., `https://docs.zenon.network`) and `DOCS_BASE_URL` (`/`).
